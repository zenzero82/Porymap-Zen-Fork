We are creating a customized fork of the open-source Porymap project.

Original repository:
https://github.com/huderlem/porymap

The new project will be called:

Porymap Studio

Porymap Studio will remain a native C++/Qt desktop application and should stay compatible with Pokémon Gen 3 decompilation projects, especially pokeemerald-expansion.

The purpose of this fork is to dramatically simplify map creation and reduce the amount of repetitive manual work required when building large Pokémon ROM hacks.

Eventually, Porymap Studio should combine ideas and functionality from:

* Porymap
* Porytiles
* Image-to-map reconstruction
* Smart terrain painting
* Automatic tileset generation
* Collision assistance
* Build-and-test automation

However, DO NOT attempt to build all of those features yet.

The goal of this task is to create a clean, stable foundation for the fork so future development can happen incrementally.

Also identify which components should be reused for the features we plan to build later.

Do not unnecessarily redesign or rewrite existing Porymap architecture.

Phase 3 — Add “New Map From Image”

Add a new option to the File menu near the existing New Map action:

New Map From Image…

This will become one of the primary Porymap Studio features.

For this task, create the UI and image-analysis foundation only.

Do NOT attempt actual metatile reconstruction yet.

NewMapFromImageDialog

Map Information

Image

* Browse button
* Image preview

Dimensions

* Source image width
* Source image height

* Proposed map height

Automatically detect map dimensions

When enabled, calculate map dimensions based on the image and the size of the metatile grid used by Porymap.

Do not hardcode assumptions if Porymap already exposes the necessary constants.

If they cannot, show a useful warning explaining the problem.

Example:

Do not crash or silently crop the image.

Phase 4 — MapImageAnalyzer

Create:

MapImageAnalyzer

This class/service should live outside the Qt dialog.

The UI should not contain the actual image-processing logic.

MapImageAnalyzer should initially support:

* Loading an image
* Verifying the image exists
* Verifying the image can be decoded
* Reading pixel dimensions
* Determining proposed map dimensions
* Validating grid alignment
* Returning useful validation errors
* Providing the loaded image for preview/future processing

Design it so we can later extend it with:

MetatileRenderer

CollisionAnalyzer

Do NOT implement those systems yet.
